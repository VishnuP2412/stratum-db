  ### Phase 1 — MemTable, WAL, Engine (Recovery) — complete
  - `SortedDict` for MemTable; `RLock` (tombstone `delete()` calls `put()` internally); full entry footprint (not just value size) for size tracking.
  - WAL: plain `open()`/`write()`/`os.fsync()`, not `mmap` — sanctioned deviation, see above. Entry format `struct '>QBII'` + CRC32. Replay stops at first CRC mismatch, no skip-and-continue.
  - `pathlib.Path`-only enforcement, `TypeError` on `str` — first instance of the fail-loud-at-boundary pattern used throughout the codebase since.
  - Engine owns the single global `seq_no` counter. `_recover()` runs unlocked, once, in `__init__`.
  ### Phase 2 — SSTable flush — complete
  - Entry format: `key_len(4B) | val_len(4B) | seq_no(8B) | deleted(1B) | key | value`, `struct '>IIQB'`.
  - `flush()` is a classmethod/constructor: writes file, derives `min_key`/`max_key` as byproduct, returns a constructed `SSTable`. `Engine.sstables` holds instances, not paths.
  - Atomic write pattern: temp file + `os.fsync()` + `os.replace()`, single commit point. `bytes`-only enforcement at every component boundary, independently validated per-component (not trusted from `Engine`).
  - SSTable filename scheme was later changed in the sparse-index work (see Phase 4 below) — original Phase 2 counter+UUID scheme is superseded.
  ### Phase 3 (roadmap numbering) — Compaction — complete, but see Discrepancy #1
  - `Engine.compact()`: merges all current SSTables, resolves conflicts by highest `seq_no` per key, physically drops tombstoned entries (first point tombstones are actually removed from disk, not just filtered at read).
  - **Compaction trigger decision:** keep compaction explicitly manual, with no automatic/background trigger, through the current standalone build; revisit automation when deployment work begins. This is a deliberate deviation from roadmap Phase 3, which calls for a background compaction thread. Manual compaction must not be reported as satisfying that roadmap requirement.
  - **Not tiered, not \*\***`heapq`\***\*-based** — naive `SortedDict` load-all-into-memory merge. See Discrepancy #1 for the unresolved reconciliation against the roadmap's mandatory design.
  - Crash-safety ordering: new file flushed and `self.sstables` reassigned _before_ old-file deletion; deletion is per-file `try/except`, logs failures, doesn't abort the loop. Verified via mocked-`OSError`-on-unlink test, accepted as sufficient because `unlink()` is a single atomic syscall with no partial-write state. **A live SIGKILL test targeting the unlink loop was attempted multiple times and never reliably landed inside that window — do not assume one exists.**
  - `SSTable.read_entries()` extracted as the single shared generator for raw entry parsing (header unpack, truncation checks, duplicate-key check) — `scan()` and `from_file()` both consume it, neither reimplements parsing.
  - Performance finding that motivated the sparse-index work: at ~5,000 SSTables/~1M entries, `Engine.get()` measured 30+ minutes for 100,000 sequential lookups, even against a single post-compaction file — root cause traced to `scan()`'s full linear read with no way to seek, since the format is variable-length and self-describing only via sequential parsing.
  ### Phase 4 (this project's numbering) — Sparse Index and Bloom Filters — complete
  - **Scope note:** the sparse index addresses within-file seek cost; Bloom filters were subsequently implemented separately to satisfy the roadmap's Phase 4 behavior. The FPR measurement caveat is recorded in the resolved discrepancy above.
  - Design: fixed 1000-entry sample interval (not configurable — considered and rejected, since small/empty tables degrade gracefully via the search fallback rather than needing a tunable parameter). Entry 0 always unconditionally sampled, removing a "before first sample" special case downstream.
  - Storage: entries as before, then a footer appended to the `.sst` file holding the sample list (`key_len | key | offset`, repeated); a 4-byte `.idx` sidecar holds only the footer's starting offset.
  - Built inside `flush()` as a byproduct of the existing write loop — `compact()` (which calls the same `flush()`) gets a correct index on merged output for free, no compaction-specific index code.
  - Read path: `SSTable.search(key)` — bisects the in-memory sample list (`bisect.bisect_right`, minus 1, clamped to 0), seeks near the target, delegates to an extended `scan()` (new optional `offset` param, new early-exit-on-overshoot condition) rather than duplicating scan logic. `read_entries()` gained only a generic boundary parameter, no key-awareness. `Engine.get()`: one-line swap from `scan(key,key)` to `search(key)`.
  - **Real bugs found and fixed across many rounds** (kept for the record, in case a similar shape recurs): filename-collision in `compact()` from a missing `tableCount` increment (fixed to match `write_table()`'s convention); `struct.unpack()` tuple-vs-int confusion at three sites in `from_file()`; EOF-check-performed-after-unpack instead of before (crashes on every real-world footer read until fixed); a boundary check performed once before a loop instead of on every iteration inside it (silently never actually bounded anything); an `is not None` vs. truthy check on a boundary offset that mattered specifically for zero-valued-but-real boundaries (0-entry tables); a **tmp-file path bug** where `flush()`'s temp files were derived from the directory argument instead of the target file paths, causing tmp files to land one directory level up from intended — invisible under normal testing since `os.replace()` doesn't care about source directory, flagged as materially relevant given the dev environment's `/mnt/d/` NTFS-via-9p mount, where cross-directory renames aren't guaranteed the same atomicity as same-directory ones.
  - **Status of the tmp-file path fix: confirmed applied.** `SSTable.flush()` derives `tmp_sst_path` and `tmp_idx_path` from the final `.sst`/`.idx` paths, so both temporary files stay in `table_dir` and same-directory `os.replace()` preserves the intended atomicity.
  - Test coverage: SSTable-level boundary/empty/exact-match/miss cases, reactivated + updated invariant tests (duplicate-key, truncation, type-check) that had been silently commented out during the constructor-signature change (a real regression, caught and fixed — same "coverage silently narrows while pass/fail stays green" failure shape as Phase 2/3), a mocked-`os.replace`-failure test confirming `.idx` survives while `.sst` doesn't when the `.sst` commit specifically fails, a multi-table compaction test with real cross-table `seq_no` conflicts plus a post-compaction file-count assertion, and Engine-level memtable-hit/sstable-hit/tombstone/restart-round-trip/restart-shadowing/cross-table-tombstone-shadowing tests.
  - **Not built, deliberately:** live SIGKILL test for the `.idx`/`.sst` dual-commit window inside `flush()` — same reasoning as the Phase 3 compaction-unlink precedent (narrower window, less likely to land reliably than an already-inconclusive wider one; mocked-failure test judged sufficient).
  ### Phase 5 — Standalone + gRPC API — active scope
  - `Engine.scan(start_key, end_key)` returns the inclusive key range in order across SSTables and the memtable. It resolves duplicate versions by highest sequence number and suppresses tombstones.
  - The gRPC `Scan` RPC streams `KVPair` results for the requested inclusive range. `Get`, `Put`, and `Scan` are wired to the engine in `StratumServicer`.
  - `tests/test_engine_scan.py` contains nine pytest cases, including the cross-SSTable newer-tombstone mutation check: the older SSTable contains the live value, the newer SSTable contains the tombstone, and the scan returns no row. Temporarily disabling tombstone suppression made this test fail, confirming it exercises the intended branch.
  - The gRPC missing-key test asserts both `OK` status and `found=false`; temporarily changing the servicer to return `found=true` made it fail. With metadata unset, the complete default suite finished at `102 passed, 1 deselected` in the clean project venv. A fresh clone with the pending tree applied, installed via `pip install -e '.[server,dev]'`, completed at `106 passed, 1 deselected` in 2:54, proving the nested crash-writer root fix and test discovery outside the original checkout layout.
  - The independently selected slow suite (`pytest -m slow`, metadata unset) completed start-to-finish with `1 passed, 102 deselected` in 38:18. The million-entry compaction test was not reduced.
  - Initial empty-key trace: before the boundary policy was added, empty-key `Put` and `Get` both returned `OK`. The resulting decision is now explicit and implemented below: reject empty keys at the gRPC servicer with `INVALID_ARGUMENT`.
  - gRPC boundary policy: the servicer now rejects empty `key`, `start_key`, and `end_key` fields with `INVALID_ARGUMENT`; `Engine` remains unchanged. This prevents omitted proto3 `bytes` fields from silently colliding on the empty key. The inclusive `Scan` contract therefore requires both non-empty bounds. The effective maximum value size over the default gRPC transport is just under 4 MiB; larger messages receive `RESOURCE_EXHAUSTED` before the servicer.

This is one of the recurring execution mistakes that should not be relearned next time a standalone script gets written.

  1.  Tag claims: [Certain] hard evidence/trace, [Likely] strong inference, [Guessing] filling gaps.
  1.  Never use: "Great Question", "You're Absolutely right", "That makes a lot of sense", "Absolutely", "Definitely".
  1.  Disagree explicitly: "I disagree because [reason]. Here's what I'd do instead [alternative]. The risk in your approach is [specific downside]."
  1.  Uncomfortable answer first — lead with it, don't bury it.
  1.  No warm-up paragraphs — start with the most useful thing.
  1.  Hold position under pushback unless genuinely new information is provided — "but I really think" is not new information.
- Handoff Protocol
  - This single file (`STRATUM_PROJECT.md`) replaces the former separate `HANDOFF.md`/`DEVELOPMENT.md` split. Keep it as one file going forward.
  - Update it at the end of every session — reflect what was actually decided/built, not what was planned at the start. Every phase so far has diverged meaningfully from its starting plan.
  - Record explicit scope decisions here and update the roadmap when practical; until then, this file's latest explicit decision controls active scope where it conflicts with the older roadmap. Do not infer a scope change from implementation alone.
  - `TEST_INVENTORY.md` (new as of this session) should be updated alongside any change to the actual test files — treat a test file change without a matching `TEST_INVENTORY.md` update as incomplete, the same way a code change without a matching test is incomplete.
